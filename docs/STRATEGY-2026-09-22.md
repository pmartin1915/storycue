## Context

Perry asked for one session to organize and strategize finishing
both apps, collaborating with Kimi and Sol. Both repos are clean and pushed (storycue `85cbaa8`,
retold `f99a392`). Perry overrode the original "StoryCue first" ordering on 2026-09-22: build
Retold **in parallel**, not after. StoryCue's dates are fixed by hardware launch (submit
**10-16**, launch 10-23, Thanksgiving 11-26); Retold's are not.

Findings from orientation that change the picture:

1. **StoryCue "week 1 done" is the domain layer only.** WEEK1-SPEC scoped out SessionStore,
   every screen, the consent card, the library, real export and deck copy.
   `StoryCue/StoryCueApp.swift` is still the placeholder `ContentView`. The app records nothing
   yet. PLAN §9 week 1 promised "decks, capture, library, export". Against a fixed 10-16 submit,
   that is a real slip and the thing this strategy has to absorb.
2. **The runner image is mid-rollout, and both workflows pick Xcode non-deterministically.**
   `Select Xcode` does `ls -d /Applications/Xcode*.app | sort -V | tail -1`. Run `35759964133`
   landed on image `20260921.0210.1` → `Xcode_27.2_beta.app` (27B5019j, Duo SDK yes). The next
   run, `35769450879`, landed on image `20260912.0186.1` → `Xcode_27_Release_Candidate.app`
   (27.0, no Duo). So STATE's "runner now HAS the Duo SDK" is not steady state, the "baseline"
   lane sometimes builds on a beta, and **`deploy.yml` uses the same selection — an archive from a
   beta Xcode cannot be submitted for App Store review** (it *can* go to TestFlight — Apple's ASC
   release notes, per Sol). That could silently kill the 10-16 upload. Must be fixed before the first TestFlight build.
3. **Both apps are blocked on the same Perry-only acts.** Neither has an App ID, provisioning
   profile, ASC record or GitHub secrets. StoryCue's week-3 gate (TestFlight + rung-4b on the
   16 Pro) and Retold's recorder gate (launch-to-red-light on the 16 Pro) both need them. Perry's
   own calendar in the window: slides to council 9/28, Samford decision 9/30, symposium talk 10/1,
   CCTS pre-app 10/19.
4. **Retold's week 1 as written can only be gated on hardware** (recorder, SpeechAnalyzer,
   Action button, lock handling). But PLAN §4 item 4 names a large block that XCTest *can* prove
   on CI with no device: the data model, the span verifier + template assembly, the
   leading-question lint + copy lint, the question engine, `DeckFilingModel`, the export
   manifest. That block is fully specified in PLAN §5–§8 and is `/orchestrate`-shaped.
5. **Cost:** both repos are private; macOS minutes bill 10×; `build.yml` in both triggers on
   every push to main with no `paths-ignore`, so every docs/STATE commit burns a full run.
6. Retold prompt D (Apple stack) never landed — Apple-stack facts rest on Sol's review alone.

## Strategy

**Principle: StoryCue owns every contended resource until 10-16** (Perry's operator time, Opus
boss/review time, device testing). Retold runs in parallel only on lanes that contend with
nothing: CI-testable pure logic executed by Kimi, audited by Sol. That is "parallel" without
risking the one fixed date.

Not a pivot (PLAN §5 already names single-screen 1.0 as the *expected* path) — a resequence:
there is no UI to fold yet, so Duo work waits.
