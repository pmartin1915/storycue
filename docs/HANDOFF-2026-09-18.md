## What it is, in three sentences

iPhone Duo ships 2026-10-23. StoryCue is a family-interview video recorder where the
person being filmed reads the question off the Duo's **outer display** while the filmer
holds the recording UI on the inner display; decks for grandparents, parents, kids,
couples, the holiday table; nothing leaves the phone. First marketing moment is
Thanksgiving, 2026-11-26.

## The constraint stack — do not plan around a machine that does not exist

- **No Mac.** perrypc and perryslenovo are both Windows. Xcode never runs locally; Device
  Hub (Xcode 27.1's Duo simulator) is unreachable except on a hosted runner.
- **No Duo.** See above.
- **Hosted runner `macos-27`**, read from `actions/runner-images` on 2026-09-18: Xcode
  27.0 RC only, SDKs `iphoneos27.0` / `iphonesimulator27.0`, simulator runtime lists
  iPhone 17/17e/18 Pro/18 Pro Max/Air and **no Duo**. Xcode 27.1 beta (the Duo SDK) shipped
  the same day and is not on the image. **Re-read that README at every weekly gate;** the
  timeline hangs on it.
- **The platform:** the outer display hosts no scenes; `CameraCaptureAccessory`
  (registered via the SwiftUI `sceneAccessory` modifier, bindable `isEnabled`,
  `onAvailabilityChange`) is the only dual-display mechanism and needs the app full screen
  on the inner display with a live camera session. Hinge: `onHingeChange` gives
  `context.hinge?.status` in `.closed / .partiallyOpen / .fullyOpen` plus `angle`; **`nil`
  hinge = not a Duo**, which is the fallback branch, not an error. Whether the subject can
  *touch* the outer content is unconfirmed — design it display-only.

     took, so a green run cannot be mistaken for the Duo build.

     a mock on the simulator (plan §5 rung 1). Build an "outer preview" debug mode that
     renders the accessory view in a panel on any device (rung 4).
